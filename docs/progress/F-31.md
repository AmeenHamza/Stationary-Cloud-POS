# F-31 — Staff management

**Status:** COMPLETE (2026-10-30) · Phases 5 + 6 · Decisions: D-10 (only an admin creates accounts)

## What was built

- **API** (`apps/api/src/modules/staff`, permission `staff:manage`):
  - `staffUsers(filter: { search, status }, first, after)`: keyset pages by full name (max 50), lazy
    `totalCount`;
  - `createStaffUser` (taken username → `CONFLICT` with `fieldErrors.username`; password may not equal the
    username);
  - `updateStaffUser` [V] (version check; a role change revokes that user's sessions);
  - `setStaffUserStatus` (disabling revokes sessions);
  - `resetStaffPassword` (revokes sessions; `password` rate limit).
  - Last-admin guard: the target and all active admins are locked in ascending id order, so two admins
    disabling each other at once cannot both succeed. Every change is audited (`staff.*`).
- **Web** (`apps/web/src/features/staff`): Staff screen with server-side search, status filter, keyset
  Previous/Next pages, Add staff, Edit (name, role), Reset password, Enable/Disable with confirmation.

# F-41 — Delete on the admin pages (and the verification of F-38 to F-42)

**Status:** COMPLETE (2026-11-09) · Owner update · Rules: D-28, BR-26, ADR-046

The owner asked for a delete that removes data from the database, and chose "safe delete" over deleting
history: a row goes only if no bill, khata entry or recorded work depends on it. Everything else is refused with
`HAS_HISTORY`, and Archive or Disable remain. Bills and khata entries have no delete at all (D-12).

| Page | Delete does | When refused |
|---|---|---|
| Products, Low stock | Removes the product, its stock history and the import rows that created it; clones stay, unlinked | It is on any bill: archive it |
| Categories | Already removed the category; its products move to Uncategorised | Never |
| Customers | Removes the customer | Any bill or khata entry: archive them |
| Vendors | Removes the vendor | Any khata entry: archive them |
| Staff | Removes the account and its sessions; its sign-in logs stay without the name | Bills, refunds, stock or khata entries, imports, settings, other accounts or any other audited action: disable it. Also your own account and the last active admin |
| Order history | No delete (D-12) | |

- **Who:** admins only, through the existing archive permissions. Every delete asks first and is audited.
- **At other counters:** a deleted product leaves open screens through `product.changed` (`DELETED`), and its
  lines leave any open cart.
- **Races:** deleting a product takes the row lock a sale takes, so one always sees the other.

## Found and fixed while testing

1. **Deleting an imported product crashed.** `import_job_rows_product_ck` requires a succeeded row to keep its
   product, so unlinking the row was refused. Those rows are working data, so they now go with the product.
2. **A scan could also send a name search (old bug, F-18).** Enter did not cancel the search box's pending search.
   See [F-38](F-38.md).
3. **A stale e2e expectation.** `billing.spec` looked for cart text that had changed before this work.

## Limitations

- **A discount-test hang was not reproduced.** E2E-16 hung once at a bare 30 s timeout, with no locator named.
  The likely cause is `liveChannel`, which waits for the socket with no timeout, while the suite shares the
  `ws-connect` limit of 30 per minute per IP. The logs could not confirm it. `counter-tools.spec` and `delete.spec`
  now share one page per role, and it did not recur in three runs.
- **The offline banner test failed once in 13 full runs.** `realtime.spec` F-37 goes offline right after signing in,
  and the banner did not show within 5 s. This work changed neither the test nor the banner. The cause is not
  known.
- **One failing test can fail another.** A failure restarts Playwright's worker, which forgets `signInOnce`
  sessions; the extra sign-ins then reach `login-ip` (30 per 15 minutes), and the last staff test fails with "Too
  many attempts". Read the first failure in a run first.
- **`pnpm verify` can fail with a Prisma file error.** `@pos/database`'s `lint` and `build` both run `prisma
  generate` and can collide (seen twice, on code that was already there). Running `turbo run build
  --filter=@pos/database` first avoids it.
- **Real 80 mm printer:** the receipt's new rows were checked on screen in print mode, not on paper.

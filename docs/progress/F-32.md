# F-32 — Stock adjustment (admin)

**Status:** COMPLETE (2026-10-31) · Phase 7 · Decision: D-18 · Rule: BR-24

## What was built

- `adjustStock(input: { idempotencyKey, productId, direction, quantityPieces, reason, note })` [K]
  (`inventory:adjust`, admins only). It writes an `ADJUSTMENT_INCREASE` or `ADJUSTMENT_DECREASE` movement with
  a required reason (`DAMAGED`, `LOST`, `COUNT_CORRECTION`, `OTHER`), and may take stock below zero (D-16).
  The audit row `stock.adjusted` records the direction, pieces, reason and resulting stock.
- Database CHECKs enforce the movement sign per type and "reason if and only if adjustment".
- Web: "Adjust stock" dialog with direction, pieces, reason and an optional note.

## What was built

**Database** (`packages/database/prisma/schema/catalog.prisma`, migration `20261030111102_catalog`):
- `categories` (`citext` unique name); `products` (prices `numeric(12,2)`, stock in pieces, threshold in
  pieces, `cloned_from_id`, `idempotency_key` + `request_hash`, `archived_at`, `version`);
  `stock_movements` (append-only ledger with `balance_after`, reason, idempotency).
- CHECKs: names, prices ≥ 0, box price only with pieces per box > 1 (D-17), tax 0–100, the idempotency
  key/hash pair, the movement sign per type, reason if and only if adjustment.
- Partial indexes: active barcode unique, active name/category/price, low stock; trigram indexes for search.

**API** (`apps/api/src/modules/catalog`, `modules/settings`):
- Products:
  - `products(filter, sort, first, after)`: keyset by name or price, then id; server-side search on name,
    Urdu name and exact barcode; filters for category, Uncategorised, low stock only, include archived.
  - `product`, `productByBarcode` (active only), `productsByIds` (≤ 50).
  - `createProduct` [K]: `OPENING` movement.
  - `updateProduct` [V]: stock is never edited here (BR-03); the audit records changed field names only.
  - `cloneProduct` [K]; `archiveProduct` / `restoreProduct` (products are never deleted).
  - `costPrice` resolves for admins only (field middleware, SEC-03).
  - Duplicate active barcode → `CONFLICT` with `fieldErrors.barcode`; stale version → `CONFLICT`.
- Shop settings:
  - `shopSettings` (every role), served from the Redis reference cache; `updateShopSettings` [V] (admins),
    with outbox `settings.changed` and generation invalidation after commit.
- Events:
  - `product.changed` (public snapshot, `null` if it would exceed 1 KB), `stock.changed`, `category.changed`.
  - `lowStock.countChanged` (admins) on every threshold crossing.

**Web** (`apps/web/src/features/catalog`, `features/settings`):
- Products screen: server search, category filter, sort, low-stock and archived toggles, keyset pages, row
  menu.
- Add/Edit form: two columns; the threshold is entered in pieces or boxes; the cost price is loaded only for
  the edit form.
- Clone, Restock (with preview) and Adjust dialogs.
- Categories grid with "View products" → `/products?category=<id>`; Low stock screen; sidebar badge.
- Settings screen.
- New admin navigation: Products, Categories, Low stock (live badge), Staff, Settings, Billing terminal.

**Development seed** (`pnpm db:seed` → `packages/database/seed/seed-dev.ts`): six categories and 25 generic
stationery products, some in boxes and some low on stock. It is fake data only, local hosts only (guard),
and does nothing if categories exist. It was run twice on the local `pos_dev`: the first run seeded, the second
did nothing.

**Shared:**
- `@pos/validation` schemas (category, product, inventory).
- `@pos/domain`:
  - `piecesToThreshold`, `splitPieces` (100 % coverage kept);
  - `restockPieces`, `thresholdToPieces`, `normalizeNameKey` reused.
- `components/data`: `CursorPager` (pages + connection) and `EmptyState`, now shared by staff, products and
  categories.

## Defects found and fixed on the way

1. **The products page exceeded the query cost limit.** The API refused the products page with "complexity
   1301 > 1000" (found by e2e). The cost model now charges rows and nesting, not scalar columns; the 1,000
   limit is kept (ADR-035). A SEC-09 integration test shows that a full page passes and 20 pages in one
   request are refused.
2. **Invalid variables became internal errors.** A null for a required enum came back as
   `INTERNAL_SERVER_ERROR`, because complexity analysis coerces variables first. It is now `BAD_USER_INPUT`
   (unit test added).
3. **Test database drop failed under autovacuum.** It failed when an autovacuum worker held the database.
   `@pos/testkit` now retries the drop, waiting on the server with `pg_sleep`.

## Limitations

- **Integration stability.** Seven full API integration runs on this PC. The last three in a row passed
  completely (84/84, 84/84, 91/91). The four earlier runs each had one file fail:
  - `cache.int.spec` (Phase 4): a Redis command timed out while its harness started.
  - `staff.int.spec` (Phase 5): the harness start exceeded the 120 s hook timeout, in a run that took 534 s
    instead of the usual 55–145 s because the machine was heavily loaded.
  - `staff-last-admin.int.spec` (Phase 5): failed once. Its error output was not captured; it passes alone
    and in every later run.
  - `catalog-lists.int.spec`: its teardown failed because an autovacuum worker held the database. This was
    real, and fixed in `@pos/testkit`.

  The first three point to load on this machine (WSL services, cold starts), not to the features. They will be
  re-checked in CI.
- **NET-01 margin is small.** A 50-row admin page with long English and Urdu names is 24,739 B of the 25 KB
  budget. Field trimming is a Phase 14 measurement item.
- **Not built yet:** the stock history screen (P-02, awaiting the owner) and CSV/PDF exports (F-11, Phase 11).

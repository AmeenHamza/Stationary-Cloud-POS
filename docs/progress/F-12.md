# F-12 — Categories

**Status:** COMPLETE (2026-10-31) · Phase 7 · Decisions: Q16b (delete moves products to Uncategorised)

## What was built

- API (`catalog:read` / `catalog:write`):
  - `categories(filter: { search }, first, after)`: name-ordered keyset pages (case-insensitive `citext`),
    with `productCount` per page from one grouped query. The unfiltered first page comes from the Redis
    reference cache (generation-invalidated by category and product commands, RED-03).
  - `category(id)`, `createCategory`, `updateCategory` [V]; a duplicate name (any case) →
    `CONFLICT fieldErrors.name`.
  - `deleteCategory(id)` moves its products to Uncategorised (their version + 1) in the same transaction.
  - `category.changed` events; audit `category.*`.
- Web: Categories grid (card per category: count, View products, Add product, Edit, Delete with
  confirmation that names how many products move). "View products" opens `/products?category=<id>`, which is
  the category detail with the 50-row keyset contract.

## Limitations

- Product counts in other admins' open category grids update on the next category change or navigation;
  creating a product emits no category event (SYSTEM_DESIGN.md §5.9 lists `category.changed` and
  `catalog.bulkChanged` as the triggers).

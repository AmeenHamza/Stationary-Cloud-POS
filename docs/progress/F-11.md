# F-11 — Product import, template and exports (and the batch 5 + 6 verification)

**Status:** COMPLETE (2026-10-31) · Phase 11 · Rules: Q14 (match by barcode), Q37 (template columns; unknown
categories fail), BR-03 (stock only for new products), ADR-020, ADR-040

## What was built

- **Upload** `POST /v1/imports/products` (admins, `X-POS-CSRF: 1`, ≤ 5 MB, .xlsx or .csv by its real bytes,
  ≤ 5,000 rows):
  - Every row is validated at upload. A bad cell, a barcode repeated in the file, or an unknown category
    fails that row.
  - The job and its rows are stored in PostgreSQL, then queued; the response is `202 { importJobId }`.
- **Worker** (BullMQ via `QueueRuntime`, one job at a time):
  - It applies `PENDING` rows in batches of 100, one transaction each. A barcode match updates the
    product's attributes; otherwise the product is inserted with its opening stock and an OPENING movement
    linked to the job.
  - It sends `import.progressed` to the importing admin and, at the end, one `catalog.bulkChanged` and a
    low-stock recount.
- **Template** `GET /v1/imports/products/template.xlsx`. **Error report** `GET /v1/imports/:id/errors.csv`.
  **Queries** `importJob(id)` and `importJobRows(jobId, status)`.
- **Exports** `GET /v1/exports/products?format=csv|xlsx|pdf` and the low-stock export (F-13):
  - Rate-limited, audited and streamed in batches of 500.
  - Columns are the template's headers, and formula-like text is escaped.
- **Web:**
  - Products: Import (template link, file, live progress bar, the refused-rows download) and Export
    (CSV / Excel / PDF).
  - Low stock: CSV / PDF.
  - `catalog.bulkChanged` triggers one recovery refetch.

## Found and fixed

1. **Shutdown hung while Redis was down.** An API started while Redis was down never finished shutting
   down with `@nestjs/bullmq` (found by `schema:emit`). BullMQ now starts only once Redis is ready, and
   shutdown is capped at 5 s (ADR-040).
2. **The docs disagreed on the import rate limit.** API.md said it fails closed when Redis is down, while
   ADR-020 and RED-08 say uploads must still stage. It now falls back to per-instance memory, like `login`.
3. **The test harness let one instance take another's job.** Two API instances in one test file share the
   test Redis and queue but not the database, so one instance took the other's job. RED-08 now has its own
   spec file; production instances share one database, so this is test-only.

**Start-up flake: root cause found and fixed.** This is the "known start-up timeout" noted under F-22.
- **Cause:** the test harness waited for each Redis client's `ready` event with Node's `events.once`, which
  rejects on any `error` event. On a loaded machine, ioredis's ready check (`INFO`) can exceed the cache
  client's 200 ms command timeout. The client then emits a transient `error` and reconnects, which the API
  tolerates by design, but the harness failed the whole file.
- **Fix:** `waitForStatus` in `test/support/harness.ts` now waits for the status event only, still bounded
  at 15 s. It is checked by the batch 7 integration runs (F-29).

**Compliance audit:**
- No polling: live dashboard updates come from events and import progress comes from
  `import.progressed`.
- Lists:
  - Import rows are keyset-paged (≤ 50).
  - Exports stream in batches of 500 with bounded statements.
  - Dashboard lists are bounded and on the allow-list (12, 31, 6 and 10 rows).
- Events are ≤ 1 KB. Redis holds only BullMQ work items (RED-11 updated).
- Every handler is guarded (SEC-01). CSRF header, upload limits and magic-byte checks are covered by SEC-14.
- The import applies rows in transactions of 100 with an OPENING movement per new product; stock-ledger
  integrity is checked.

## Limitations

- **Export memory:** the export memory test checks bounded reads (statements per batch) and streaming
  (chunked responses), not a measured heap ceiling.
- **PDF:** the PDF omits Urdu names (its built-in fonts have no Urdu glyphs); CSV and XLSX include them.
- **Accepted advisories:** two moderate, transitive advisories in exceljs's dependencies (ADR-040).

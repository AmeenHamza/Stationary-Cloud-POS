# F-30 — Groq API key management

**Status:** COMPLETE (2026-11-01) · Phase 12 · Rules: D-22, Q17b (one shop key in Settings), SYSTEM_DESIGN.md
§9.1, ADR-026, ADR-041

## What was built

- **Storage:**
  - `shop_settings.groq_api_key_ciphertext` holds the key AES-256-GCM encrypted (`SecretBox`, key
    `SETTINGS_ENCRYPTION_KEY`, nonce ‖ ciphertext ‖ tag).
  - `groq_api_key_last4` is the only fragment ever returned.
  - Migration `20261101090000_ai_key_pair` (additive) adds `shop_settings_ai_key_ck`: both columns are set
    and cleared together, and `last4` is exactly 4 characters.
- **API:**
  - `setAiApiKey(input: { apiKey })` and `clearAiApiKey` (`settings:write`) return `ShopSettings`, emit
    `settings.changed` and write the audit rows `settings.aiKeySet` / `settings.aiKeyCleared`, which have no
    metadata.
  - `ShopSettings.aiKeyConfigured` and `aiKeyLast4` are field resolvers guarded by `settings:write`, so a
    cashier asking for them gets `FORBIDDEN` (SEC-03).
  - The key is decrypted only inside an AI request (`AiKeyService.apiKey()`). It is never cached; it is
    redacted from logs by `*.apiKey`.
  - Validation: 20–200 characters, no spaces, trimmed.
- **Web:** Settings has an "AI Assistant (Groq)" card (`AiKeyForm`):
  - a status line ("Configured · Key ending •••• abcd" or "Not configured");
  - a masked input with a Show/Hide toggle, which masks itself again after saving;
  - Save, and Remove when a key is set.
  - Other admins' screens refresh after `settings.changed` (`AiKeyStatus` is a live query).
  - AI pages show a "Add the shop's Groq API key in Settings" notice until a key exists.

## Found and fixed

- **`ShopSettings.updatedAt` could not be read since Phase 7.**
  - The profile is cached as text, but `GraphQLISODateTime` serialises only `Date` values (a string becomes
    `null`, an error on a non-null field). No client asked for the field, so nothing failed.
  - It is now a field resolver, covered by `settings-events.int.spec`. `AiResult.generatedAt` had the same
    problem and was fixed the same way (ADR-041).

## Limitations

- **Encryption-key rotation:** rotating `SETTINGS_ENCRYPTION_KEY` makes the stored key unreadable. The AI pages
  then say "Enter it again in Settings". A re-encrypt CLI is planned with the Phase 15 runbook
  (SYSTEM_DESIGN.md §9.1).
- **Key not checked on save:** the key is not tested against Groq when saved. A wrong key shows up on the
  first AI request as "Groq refused the API key. Replace it in Settings."

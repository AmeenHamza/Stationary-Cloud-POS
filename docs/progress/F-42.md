# F-42 — Imports create categories; exports carry them

**Status:** COMPLETE (2026-11-08) · Owner update · Rules: D-29, Q37, ADR-047 · Builds on F-11

- **Import:** the categories a file names are created first, in the same transaction as the staged job, then
  each product goes into its category. Names match ignoring case, and the first spelling in the file wins. A
  blank cell means Uncategorised. A refused row creates nothing.
- **Legacy files:** a `category_name` column is read as Category.
- **Export:** CSV, Excel and PDF already had a Category column, so nothing changed there; a test now holds it.
  An exported file imported again brings a deleted category back and refiles its products.
- **Template:** its example row now shows a category.

## Limitations

- **A mistyped name** now creates a new category instead of failing its row. Fix it on the Categories page.
- **Categories with no products** are not in an export, because the file has one row per product.
- **Stock in an export:** the "Stock (pieces)" column is not read as "Opening stock", so importing an export into
  an empty shop brings products in at 0. Rename the column to import stock.

# F-29 — AI Assistant (six features) and the batch 7 verification

**Status:** COMPLETE (2026-11-01) · Phase 12 · Rules: D-22 (keep all six), Q17 / Q17b (data sent, key),
BR-15 (advice only), Q38 (defaults), ADR-026, ADR-041 · Key management: [F-30](F-30.md)

## What was built

- **API (`modules/ai-assistant`), admins only (`ai:use`), six mutations returning
  `AiResult { text language generatedAt cached }`:**
  - `aiSalesInsights(periodDays 7/14/30/60/90)`.
  - `aiInventoryForecast` (30-day velocity) and `aiPurchaseRecommendations` (45-day velocity, pieces for 30
    days and their estimated cost).
  - `aiBusinessReport(DAILY | WEEKLY | MONTHLY | CUSTOM ≤ 92 days, not after today)`.
  - `aiDiscountAdvice` (slow stock, recommendations only).
  - `aiAsk` (chat over five read-only tools, ≤ 3 tool rounds, history ≤ 10 turns / 4,000 characters, never
    stored).
  - Every request takes one path (ADR-041): validation, the `ai` rate limit (30 per hour, fails closed), the
    decrypted key, the 15-minute Redis cache with single-flight, then the `ai.requested` audit row.
- **Data:** bounded aggregates from `reporting`.
  - `InsightsService` and `InsightMetricsRepository`, plus a `netProductSales` CTE shared with the dashboard
    ranking.
  - Product names and numbers only: no ids, customer names or phones.
- **Groq:** `infrastructure/ai/groq.client.ts`.
  - Model `GROQ_MODEL`, default `openai/gpt-oss-120b` (U-05), low reasoning effort with no reasoning text
    returned.
  - Output ≤ 4,096 tokens, 30 s timeout, one retry on a 5xx.
- **Web `/ai`** (admin sidebar "AI Assistant"):
  - A home page with the six features and the Admin only / Live data / 3 languages badges.
  - A feature page per feature: language (English / اردو / Roman Urdu), period inputs, Generate, the answer
    with when it was made and a "Saved answer" badge when cached.
  - Business reports print on A4.
  - The chat has suggested questions and Clear.
  - Answers render through a sanitising Markdown renderer, Urdu right to left.

## Found and fixed

1. **Daily, Weekly and Monthly reports could not be generated from the screen** (found by E2E-14).
   - The form sent its empty date fields as `''`. The shared schema accepts `null` for "no date" and refused
     `''` with "Use the date format YYYY-MM-DD".
   - `lib/report-input.ts` now sends empty fields as `null`, with a unit test for each case.
2. **`AiResult.generatedAt` and `ShopSettings.updatedAt` failed to serialise** (strings, not `Date`), found
   by the first integration run; see [F-30](F-30.md#found-and-fixed).
3. **Product ids reached the prompt.** Ranking rows carried product UUIDs into the prompt, which wasted
   tokens and exposed internal ids. Prompts now carry names and numbers only, and the test refuses any UUID.

**Compliance audit:**
- **No polling:** AI calls are mutations run on a click. The key status refreshes on `settings.changed`.
- **Bounded data:** no list is unbounded. Prompts carry ≤ 50 rows per list. Chat tools have bounded
  arguments. The history is ≤ 10 turns.
- **Redis:** holds only cached answer text for 15 minutes (ADR-026), never records. A Redis failure only
  bypasses the cache. The `ai` limit fails closed by design, which never affects billing.
- **Security:**
  - Every mutation is `ai:use` or `settings:write`; SEC-01 passed.
  - The key fields are field-guarded (SEC-03).
  - The key is never returned, logged or audited (SEC-11).
  - Prompts carry no customer data or ids (SEC-12).
  - Answers render without HTML, links or images.
- **Transactions:** setting or clearing the key, the outbox event and the audit row commit together. AI
  requests read only.
- **Regressions:** the full integration and e2e suites are green.

## Limitations

- **Real Groq not called:** every test uses the stub, so answer quality in Urdu and Roman Urdu has not been
  seen with the real model yet. The owner should try each feature once with the shop's key before go-live.
- **Freshness:** answers are cached for 15 minutes per feature, inputs, language and business date. A sale
  made in that window shows up after 15 minutes or the next day; the "Saved answer" badge says when an answer
  came from the cache.
- **Typed text reaches Groq:** chat questions are sent as typed. If someone types a customer's name, it goes
  to Groq. Data from the database never includes customers (Q17b).
- **Rate limit:** cached answers count towards the 30 requests per hour (API.md §8), which keeps the limit
  simple and still bounds cost.

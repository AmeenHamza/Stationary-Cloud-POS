# F-37 — Live updates and the connection banner

**Status:** COMPLETE (2026-10-31). The live channel, banner and offline detection shipped in Phases 6–7; the
second half, "billing disabled while offline" (D-05), shipped with the payment dialog in Phase 9. Decisions:
D-05, ADR-007, ADR-036, ADR-038.

## What was built

- **API realtime module** (`apps/api/src/modules/realtime`): one `shopEvents` subscription over graphql-ws on
  `/graphql`.
  - Admission on `connection_init`: Origin must be the web app (`4403`), `ws-connect` rate limit per client IP
    (`4429`), session cookie (`4401`), at most 10 sockets per user. Only subscriptions run over the socket, at
    most 3 per socket.
  - `EventStream` per subscription. Staff, admin and per-user channels are chosen by role (RT-02). Events over
    the queue limit become `system.resyncRequired`. `session.revoked` for the socket's own session closes it
    with `4401`.
  - `RealtimeHub` sends `system.resyncRequired` to every socket when the Redis subscriber reconnects (RT-09).
  - `ShopEvent` GraphQL interface with one concrete type per event (`resolveType` from `EVENT_DEFINITIONS`).
- **Web realtime layer** (`apps/web/src/lib/realtime`, `providers/RealtimeProvider.tsx`):
  - One graphql-ws client per tab with jittered backoff (500 ms … 30 s), no retry on `4401`/`4403`, and a 20 s
    protocol ping (not polling).
  - LRU de-duplication of 1,000 `seq` values; a router by `__typename`.
  - Entity patches gated on a newer `version`: `stock.changed`, `product.changed`, `category.changed`.
  - Aggregate signals refetch mounted queries only, coalesced to one per 1.5 s: low-stock count and list,
    categories, settings.
  - Reconcile after a reconnect or resync: evict unused list fields, then refetch the active queries.
- **Banner** (`components/layout/ConnectionBanner.tsx`) in the admin shell and the terminal: amber "Live
  updates paused, reconnecting…" and red "Offline: billing paused". `useOnlineStatus` combines
  `navigator.onLine` with HTTP reachability, which the Apollo links record (`lib/apollo/network-status.ts`).

## Defects found and fixed on the way

- **Per-socket subscription cap.** The cap counted open streams, so several subscribes sent together could
  exceed it. It now counts graphql-ws's id reservations.
- **Missing banner on a failed first connection.** The banner only appeared after a socket that had connected
  once. It now appears after any failed attempt.

## Billing while offline (Phase 9)

- "Process Payment" is disabled, with "Offline: billing paused.", while `useOnlineStatus()` is false: the
  browser is offline, or the last HTTP request failed at network level.
- A sale whose response was lost is re-sent with the same idempotency key once the network returns, and it is
  confirmed exactly once (SYSTEM_DESIGN §3.4).
- Back online after a request failed at network level, the `online` event runs recovery at once (refetch
  of the active queries). The banner clears within seconds instead of after the socket's back-off.
  - Found by the full e2e run: a screen loading while the network dropped kept the red banner for up to
    30 s.
  - The realtime e2e test now fails a request while offline and expects the banner gone within 15 s.
- E2E-08 (`billing-resilience.spec.ts`):
  - `setOffline(true)` disables the button and shows the message; going back online enables it.
  - With a dropped `createSale` response, the server records the sale, the counter shows "Confirming
    sale…", retries, and the stock drops once. PASS.

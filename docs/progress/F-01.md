# F-01 — Login and logout

**Status:** COMPLETE (2026-10-30) · Phases 5 + 6 (built together, ADR-034) · Decisions: D-10 (no sign-up)

## What was built

- **API** (`apps/api/src/modules/auth`): `login` (public, rate-limited), `logout`, `me`; server-side sessions
  (`__Host-pos_sid` cookie: HttpOnly, Secure, SameSite=Strict, Path=/; 7-day absolute, 12-hour idle expiry);
  argon2id hashing with constant work for unknown usernames; one generic error for every failure; audit rows
  `auth.loginSucceeded` / `auth.loginFailed` (reason only, never the typed username) / `auth.logout`.
- **Session resolution** (`SessionService`): Redis principal cache (300 s, `NX` fills) with `REVOKED`
  tombstones; PostgreSQL decides on every miss; touch at most every 15 minutes; works with Redis down.
- **Revocation** (`SessionRevocationService`): rows revoked in the use-case transaction, `session.revoked`
  events (≤ 20 ids each, under 1 KB) in the outbox, tombstones written after commit.
- **Access control** (`common/auth`): `@Public` / `@Authenticated` / `@RequirePermission` on every handler and a
  fail-closed global `AccessGuard` (ADR-033).
- **First admin**: `pnpm --filter @pos/api cli:create-admin --username <name> --full-name "<Full Name>"`
  (password prompted or piped, never an argument; refuses when an active admin exists).
- **Web** (`apps/web`): login page (no sign-up link), `ViewerGate` (one `me` per page load), role redirect
  (admins → Staff, cashiers → Billing terminal), account menu with sign-out, session-ended handling (any
  `UNAUTHENTICATED` clears the Apollo cache and opens /login).

## Compliance audit

| Rule | Evidence |
|---|---|
| No polling | `check:no-polling` PASS; the web fetches `me` once per page load; no timers |
| Pagination | no list in this feature |
| Minimal transfer | Prisma `select` on every query and write (`prisma-take` PASS); `Viewer` is 5 fields |
| Redis | cache only (principal ≤ 300 s); a Redis outage never blocks login, `me` or logout (tested) |
| Security | argon2id; generic errors; rate limits `login`/`login-ip`; `__Host-` cookie; CSRF prevention; SEC-01 |
| Transactions | session, audit and outbox writes share one `UnitOfWork` transaction |
| Secrets/PII | no passwords, tokens or typed usernames in logs, audit metadata or events |

## Limitations

- Sockets are closed on `session.revoked` once the realtime module exists (Phase 5 step 5); until then a
  revoked session is refused on its next HTTP request.
